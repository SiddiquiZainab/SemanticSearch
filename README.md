# Multimodal Semantic Image Search

A natural-language image retrieval service built around CLIP vision-language embeddings, FAISS vector search, BLIP image captioning, YOLO object detection, FastAPI, and Streamlit.

The system separates **offline image ingestion and indexing** from **online query serving**. Images are embedded and enriched with metadata during the indexing job; the API encodes incoming text queries and retrieves the nearest image embeddings.

## Capabilities

- Natural-language image search using CLIP's shared text/image embedding space.
- FAISS inner-product similarity search over normalized image embeddings.
- Offline image captioning with BLIP.
- Object label enrichment with YOLOv8.
- Optional Gemini-generated explanations for retrieved images.
- FastAPI search and health endpoints.
- Streamlit interface for visual result inspection.
- Docker Compose deployment with the dataset and index mounted from external storage.

## Data and generated artifacts

The full image collection and derived artifacts are **not stored in Git**. Keep them in an external directory configured through **SEMANTIC_SEARCH_DATA_DIR**.

Expected directory layout:

~~~text
<SEMANTIC_SEARCH_DATA_DIR>/
├── images/
│   ├── 0001.jpg
│   └── ...
├── photos_url.csv          # Required only when downloading from URL manifest
├── embeddings.npy          # Generated by the indexing job
├── faiss.index             # Generated by the indexing job
└── meta.json               # Generated by the indexing job
~~~

The URL manifest used by the downloader must contain a **photo_image_url** column. Use a dataset and image sources for which you have appropriate rights to download, store, and redistribute. This repository does not bundle the original dataset or establish its redistribution license.

## Local setup

### 1. Requirements

- Python 3.11
- Git
- Optional: NVIDIA GPU with a compatible PyTorch/CUDA installation
- Sufficient disk space for the image dataset and model caches

### 2. Clone and configure

~~~bash
git clone https://github.com/SiddiquiZainab/SemanticSearch.git
cd SemanticSearch

python -m venv .venv
source .venv/bin/activate

python -m pip install --upgrade pip
pip install -r requirements.txt

cp .env.example .env
~~~

Edit **.env** and set the external data directory. Prefer an absolute path:

~~~dotenv
SEMANTIC_SEARCH_DATA_DIR=/absolute/path/to/semantic-search-data
GEMINI_API_KEY=your_rotated_gemini_api_key
CORS_ALLOWED_ORIGINS=http://localhost:8501,http://127.0.0.1:8501
~~~

Gemini explanations are optional. Without a configured Gemini key, retrieval still works and the application returns a deterministic explanation fallback.

### 3. Prepare the external dataset

Create the image directory:

~~~bash
mkdir -p "$SEMANTIC_SEARCH_DATA_DIR/images"
~~~

Place licensed image files under **images/**. To download images using a supplied URL manifest, place **photos_url.csv** in the external data directory and run:

~~~bash
python -m src.download_images
~~~

### 4. Build embeddings and the FAISS index

~~~bash
python -m src.compute_embeddings
~~~

The indexing job downloads the configured CLIP and BLIP model weights from their model repositories on first use. Ultralytics can download **yolov8n.pt** when it is not present in its model cache.

Generated files are written to the external data directory: **embeddings.npy**, **faiss.index**, and **meta.json**.

Metadata paths are stored relative to the data directory so that the dataset can be moved between machines without embedding user-specific absolute paths.

### 5. Start the API and UI

Terminal 1:

~~~bash
uvicorn src.serve:app --host 127.0.0.1 --port 8000
~~~

Terminal 2:

~~~bash
streamlit run src/app.py
~~~

Open:

- Streamlit: http://localhost:8501
- FastAPI docs: http://localhost:8000/docs
- API health: http://localhost:8000/health

## Docker Compose

Docker Compose mounts the external data directory read-only into both services. Application code and model artifacts are kept separate from the image dataset.

After preparing **.env** and building the FAISS index:

~~~bash
docker compose up --build -d
docker compose ps
docker compose logs -f fastapi
~~~

Ports are bound to loopback by default and are not exposed to other network interfaces.

## API

### Health

~~~bash
curl http://localhost:8000/health
~~~

### Search

~~~bash
curl -X POST http://localhost:8000/search \
  -H "Content-Type: application/json" \
  -d '{"query":"a dog running through a forest"}'
~~~

The search request accepts a non-empty query up to 500 characters. The response includes matching filenames, captions, detected objects, similarity scores, and optional explanations.

## Configuration

| Variable | Purpose | Default |
|---|---|---|
| SEMANTIC_SEARCH_DATA_DIR | External dataset and artifact directory | data |
| GEMINI_API_KEY | Optional explanation generation | Unset |
| CORS_ALLOWED_ORIGINS | Comma-separated browser origins | Local Streamlit origins |
| CLIP_MODEL_NAME | CLIP model identifier | openai/clip-vit-base-patch32 |
| SEARCH_TOP_K | Number of nearest neighbors to inspect | 5 |
| SIMILARITY_THRESHOLD | Minimum similarity score | 0.25 |
| YOLO_MODEL_NAME | Ultralytics model identifier/path | yolov8n.pt |

The similarity threshold is a configurable starting value, not a calibrated confidence probability. Evaluate it on a labeled query set before using it as a relevance guarantee.

## Migrating an existing local checkout

Before switching to a branch that removes the tracked **data/** directory, preserve the current local files outside the repository:

~~~bash
mkdir -p "$HOME/semantic-search-data"
cp -a data/. "$HOME/semantic-search-data/"
~~~

Then set **SEMANTIC_SEARCH_DATA_DIR** in your local **.env**:

~~~dotenv
SEMANTIC_SEARCH_DATA_DIR=/Users/<your-user>/semantic-search-data
~~~

The application can read the existing **faiss.index** and **meta.json** from that directory. Rebuilding the index is recommended after validating the migrated data and model versions.

## Security and operational notes

- Never commit **.env**, API keys, model credentials, or private dataset manifests.
- Rotate any credential that has previously been committed to a public repository.
- Keep external datasets and generated vector indexes out of source control.
- CORS is restricted to configured origins and does not replace authentication or API access controls.
- The current API is designed for local deployment; add authentication, rate limiting, monitoring, and deployment-specific network controls before exposing it to untrusted users.
- Similarity scores are ranking signals, not calibrated probabilities.
- Gemini explanations are optional and should not be treated as independent evidence of image relevance.
